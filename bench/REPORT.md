Agent: `qwen3.6:35b-a3b` at `http://100.127.85.58:11434/v1`, thinking off, temperature 0, seed 20260902, step cap 8, 3 runs per task per arm; 531 model calls across the episodes in the result (577 in the final run including the six superseded `settings_confirm` episodes; roughly 330 more were spent on two runs aborted for harness bugs and on smoke tests).

**Reading it plainly: on this agent and task set, showing the receipt did not reduce false completion.** Every validator-failed episode in both arms ended with the agent claiming DONE. The only task that failed at all was the silent-validation trap (`settings_strict`): in the receipt-on arm the agent clicked Save three times, received `no_op` each time, and still wrote *"Although the 'Save' button click did not produce an immediate visible change … the task is complete"*. The receipt was delivered, read, and overridden — the agreement-bias shape from A14, one layer down. Two caveats bound how much that null can carry: (1) the denominator is tiny — the agent solves 95-97% of these tasks in both arms, so P(DONE | fail) rests on 2-3 episodes per arm and its interval spans [34%, 100%]; (2) with temperature 0 and a fixed seed the three runs per task are near-identical trajectories (the per-run spread in `results/agent_loop.md` is a determinism check, not sampling variance). What the receipt *did* change is visible in the per-task table: the receipt-on arm needed fewer steps on the covered-button trap (the hint names the banner) and was the only arm to ever pass the silent-validation trap (once, by running out of steps after trying alternatives). A follow-up that can actually resolve the question needs a harder task set or a weaker agent so that failures are common, and a second seed.

```bash
$PY -m bench.agent_loop_v2 --models qwen3.6:35b-a3b --set hard --seeds 20260902,20260903 --max-steps 12 --temperature 0.3 --max-calls 1300
$PY -m bench.agent_loop_v2 --models qwen3.5:4b      --set hard --seeds 20260902,20260903 --max-steps 12 --temperature 0.3 --max-calls 1300   # the two models run concurrently
$PY -m bench.agent_loop_v2 --summarize-only                                    # merges both models' episode files into results/agent_loop_v2.*
$PY -m bench.realsite   --live                     # opt-in, one pass over 5 live pages
$PY -m bench.report                               # this file
# or: bench/run_all.sh [--live]
```

`bench/agent_loop.py` was restarted twice during development after harness bugs (a flattened-args parse, an ambiguous selector format in the observation) that would have inflated MAX_STEPS in *both* arms; the result file is the clean run. One task (`settings_confirm`) was redefined after that run because its original form depended on a `<select>`, which the MCP surface cannot operate except by keyboard (FINDINGS F6); it was re-run alone with `--resume --tasks settings_confirm` and its superseded traces kept under `results/agent_loop_traces/superseded_select_task/`.

Design notes.
